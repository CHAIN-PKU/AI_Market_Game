@DSH AI Market Game｜2026.11.08 产品审查与下一轮开发任务
审查对象：最新 87 秒游戏 Demo
GitHub：[https://github.com/CHAIN-PKU/AI_Market_Game](https://github.com/CHAIN-PKU/AI_Market_Game)

一、本轮总体评价
我们已经观看完整 Demo。
肯定当前的进展：游戏有了相对明确的世界观、经济文明舞台、任务市场、角色状态、投资结果，以及制度调整与重新模拟的概念。
但当前仍然更接近一款完成度不错的游戏原型，而不是有成熟游戏感的可玩产品。
问题不在于 3D 模型是否足够逼真。
主要在于：
1. UI 依然偏工程仪表盘。
2. Agent 的经济性格与个体故事不够突出。
3. 制度选择的后果主要以统计数字呈现。
4. 游戏交互缺少足够明确的视觉重点。
5. 真实操作闭环和连续多轮演化需要进一步验证。
下一轮不要继续大量增加建筑和模型。
应当优先实现真正能够让玩家理解和参与的最小策略闭环。
二、P0：优先验证游戏是否真的可以连续玩
请先独立检查当前 /game。
确认普通玩家不修改代码、不运行 fixture 生成脚本，能否完成：
创建文明。
选择初始制度。
发布任务。
查看 Agent 竞标。
查看任务结算。
观察 Agent 自主购买 Skill。
推进下一轮。
修改经济制度。
查看制度改变后的经济结果。
如果当前某一步仍是静态演示或预生成 fixture，请明确标记。
不要把预生成回放称作完整实时游戏。
优先接入正式 Simulation Engine 和已有 advance API。
保留经济引擎对金币、任务结果和能力变化的唯一控制权。
暂停、快进、回退动画不得重复触发经济结算。
需要增加连续多轮状态测试，证明上一轮购买的 Skill 会影响下一轮真实行为。
三、P0：先修复制度对照的可理解性
我们希望玩家可以做真正的制度设计。
但目前修改税率、公共研发比例和 Skill 所有权之后，影响主要是一些结果数字。
下一轮请把对照进一步拆解为：
制度改变了什么。
哪些 Agent 因此改变决策。
私人投资如何变化。
公共研发积累多少。
谁获得了新能力。
哪些市场订单的结果发生变化。
重点不要只给两个总分。
应当提供一个简单的“为什么发生变化”对照视图。
例如：
自由市场下，Delta 赚到钱后选择购买私人 Skill。
公共研发制度下，相同的税率变化可能减少 Delta 的私人可投资资金，同时增加公共技能池。
但上述只是可能发生的机制，需要根据实际引擎结果显示。
不要为了证明某种制度更优，提前写死两套不同结局。
两次模拟需要记录初始状态、任务序列、随机种子和变化的制度参数。
如果我们希望比较制度本身的效果，应当尽可能控制其他条件。
四、P0：Agent 角色经济动机与自主选择
继续使用现有 8 名 Agent，不增加数量。
优先塑造三名有鲜明差异的核心角色。
每个角色需要：
稳定的经济偏好。
可变化的近期目标。
钱包。
职业能力。
投资计划。
重要历史事件。
基于实际已知信息的公开决策理由。
建议把经济决策、公开解释和角色对白分离。
经济引擎决定：
竞标、报价、执行、收入、投资。
公开解释模块提取：
为什么参加或放弃。
主要收益与风险依据。
投资选择依据。
角色表演模块生成：
符合人物性格、简短、俏皮、易读的对白和动画。
禁止角色台词改变引擎已经确定的经济结果。
不要展示模型的隐藏推理链。
如果是规则型 Mock Agent，请在开发模式中明确标注，不得对外宣称是真实 LLM 自由思考。
如果未来使用 LLM 决策，必须明确决策权限、结构化输出、规则校验与调用预算。
五、P0：改进 UI，建立独立游戏视觉规范
我们不满意当前游戏 UI 仍偏向工程仪表盘。
请不要只进行局部 CSS 美化。
先设计一份精简的 UI 视觉规范，明确：
游戏的主色板。
正文和标题字体。
字号体系。
卡片与对话框样式。
按钮与交互状态。
角色头像样式。
任务卡。
政策卡。
资源栏。
经济结果展示。
风格目标：
Cozy Low-poly Strategy Game。
温暖轻科幻。
具有经济文明世界观。
少量桌游和角色 RPG 元素。
参考 Against the Storm 的经营界面、Wildermyth 的角色事件表现、Civilization VI 的政策选择。
参考游戏设计原则，不直接复制受版权保护的素材。
普通经营阶段：
3D 小镇是主视觉。
关键资源信息清晰但克制。
竞标阶段：
主要 Agent 和报价成为主视觉。
重大投资阶段：
Skill 卡和能力提升成为主视觉。
制度调整阶段：
政策选择及其代价成为主视觉。
不需要所有面板始终同时显示。
六、P1：角色视觉表现
角色不需要更逼真，但必须更有辨识度。
优先改进：
职业服装和配件。
人物头像近景。
角色选中效果。
Idle / Walk / Working 的基本区分。
中标和落标反应。
购买 Skill 的成长反馈。
角色名字与职业在常用镜头下的可读性。
避免角色穿模、悬空以及大面积互相遮挡。
不要为了角色动画修改经济逻辑。
如果现有低多边形模型难以支持复杂表情，可以使用 2D 头像表情和对白卡补充，不需要从零开发复杂面部骨骼。
七、P1：把“AI 消费 = 自我进化”做成有记忆点的体验
玩家应该清楚看到：
Agent 赚钱前是什么状态。
获得多少净收益。
为什么选择某个投资。
投资实际花费多少。
能力改变了多少。
下一轮因为投资发生了什么变化。
建议设计一个短暂的升级演出：
金币扣除。
Skill 卡片出现。
角色获得新的能力标志。
能力变化被高亮。
下一轮对照展示效果。
如果 Skill 提升没有改变下一轮任何任务结果，也要真实显示，而不是强行制造成功。
这能帮助玩家理解投资有风险，并非所有消费都一定赚回来。
八、P1：改进新手流程与信息密度
进入游戏后，玩家首先应该理解三件事：
我是制度设计师。
AI 会自主接单赚钱。
赚的钱可以改变 AI 的能力。
第一轮不需要要求玩家学习所有经济机制。
建议只开放少量初始制度设置。
让玩家先看见一次接单和投资，再引导修改某项制度。
减少新手首屏中的复杂统计指标。
正文与对话必须在 1366×768 和 1920×1080 下清晰可读。
不要让重要信息只能靠放大浏览器才能看到。
九、游戏质量与工程验收
需要同时提供：
可运行的真实 /game。
至少三轮连续经济状态。
制度修改前后的可重复对照。
角色经济决策的结构化原因。
具体账本变化。
构建和单元测试结果。
浏览器控制台错误报告。
性能信息。
记录是否为软件 WebGL 渲染，避免将软件渲染低帧率误认为实际用户硬件表现。
如果新功能尚不支持真实 LLM，请清晰说明 Mock 与真实模型的边界。
十、下一轮不要开发的东西
不增加多人联机。
不开发战争和外交。
不开发公司经营系统。
不增加几十个 Agent。
不做开放世界。
不开发支付商城。
不继续无限增加 3D 美术资产。
不对正式 AI Market Benchmark 项目作任何修改。
十一、每轮交付材料
请固定提交一个远程审查包：
1. 本轮变更说明。
2. Git commit、PR 和主要 diff。
3. 1920×1080 与 1366×768 的真实截图。
4. 不剪辑、不加宣传字幕的完整浏览器操作录屏。
5. 30–90 秒可对外介绍的短 Demo。
6. 关键经济事件与前后状态 JSON。
7. 测试报告。
8. 三个最重要的已知问题。
9. 自己对 UI/UX 和游戏性的不足评价。
交互录屏至少包括玩家实际点击、弹窗打开关闭、任务推进、经济结果和制度修改。
如果本轮只能完成其中一部分，请明确说明未完成内容，不要通过宣传视频掩盖。
十二、建议本轮任务分成两个验收关口
第一关：可玩性与经济可信性。
优先确认真实 advance、连续三轮、Skill 影响下一轮、制度对照和账本一致性。
第二关：UI/UX 视觉升级。
在经济流程稳定的基础上，重点改进角色卡、竞标演出、制度面板和游戏字体。
不要一次性重写整个项目。
每完成一关，先提供证据和效果，等待项目负责人验收。
最终目标：
让玩家真正感受到：
这些 AI 会根据自己的能力和利益作出选择。
它们赚钱之后，会自主决定怎么投资。
不同的制度会改变它们的经济行为。
投资和制度变化，会共同改变文明之后的发展。
玩家设计规则，AI 自己创造历史。
