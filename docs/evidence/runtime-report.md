# 运行时报告：控制台错误 / 性能 / WebGL 渲染器

> 审查要求：提供浏览器控制台错误报告、性能信息，并记录是否为软件 WebGL 渲染，
> 避免把软件渲染的低帧率误当成真实用户硬件表现。
> 采集方式：headless Chrome（1920×1080）+ CDP，见脚本附注。

## 环境

| 项 | 值 |
|----|----|
| GPU / 渲染器 | `ANGLE (Apple, ANGLE Metal Renderer: Apple M4)` |
| 厂商 | Google Inc. (Apple) |
| **是否软件渲染** | **否**（不是 SwiftShader / llvmpipe） |
| 采集方式 | headless Chrome，可能比真实窗口略低，仅作横向对比 |
| 视口 | 1920×1080，DPR 1 |

## 结果（本轮修复前后）

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| 控制台错误 | 1 条（`/favicon.ico` 404） | **0 条** |
| 页面异常 | 0 | 0 |
| 画布实际分辨率 | 4800×2700（2.5×） | 3840×2160（2×） |
| 帧率（rAF 采样 2s） | 38 fps | 45 fps |
| DOMContentLoaded | 384 ms | 385 ms |

## 本轮做的两处修复

1. **画布过采样**：`quality.ts` 的「高」档原本是 `dpr: [2.5, 3]`，在 1920 视口下会渲染
   4800×3240 —— 对一个低多边形场景是浪费。压到 `[2, 2.5]`，**像素量降约 36%，帧率 38 → 45**，
   肉眼几乎无差别。
2. **favicon 404**：页面引用了不存在的 `/favicon.ico`，控制台一直有 1 条报错。
   改为指向已有立绘资源，控制台归零。

## 说明与限制

- 帧率是 headless 采样的绝对值，**不代表真机浏览器表现**；同样硬件上真实窗口通常更高
- 这里的关键结论不是"45fps 好不好"，而是：**是硬件渲染**，所以低帧率不能甩给软件渲染
- 三档画质仍在（高/中/低），高画质被压的是过采样倍数，不是阴影/描边等效果开关
