# LLM 博弈心流 — 技术方案（卖点层）

> 目标：让 8 个 agent 用**真 LLM**互相博弈，思考过程对观众可见；一轮 ≤ 3 秒。
> 现状：`LlmAgentDecisionProvider` 已有，但**一次请求塞 8 个 agent**（单视角、批量），
> 且谈判文本仍是规则模板。这份方案把它换成"每 agent 独立视角 + 流式心流"。

---

## 1. 三层结构（边界必须清楚）

| 层 | 职责 | 不允许做的事 |
|----|------|--------------|
| 决策层（LLM） | 思考、报价、拉谁、给什么条件 | 直接改结算数字 |
| 校验层（规则） | 校验份额/定金/报价不越界，失败兜底 | 静默改写 LLM 的话 |
| 播放层（舞台） | 逐条上屏、可跳过、可重播 | 阻塞结算 |

结算永远只信 simulation 引擎，LLM 只产出"意图"。这是现有 `DECISIONS.md` 的纪律，继续保持。

---

## 2. 一轮的时序（延迟是体验关键）

```
t+0ms    组装 Context Pack（纯本地，<5ms）
t+0ms    并行发出 8 路请求（每路一个 agent 的视角）
t+300-600ms  第一路首个 token 到达 → 心流气泡开始逐条上屏（观众不用等全齐）
t+2000ms 收齐（或单路 2.5s 超时）→ 校验 → 引擎结算
t+2000ms+ 播放动画期间，后台预热下一轮 Context（省掉一次 RTT）
```

- 每路 `max_tokens ≤ 220`、`temperature 0.8`、`response_format: json_object`
- **单路超时只兜底那一个 agent**，不整轮重跑（避免 8 路全废）
- 失败重试 1 次；仍失败 → 该 agent 用规则决策，UI 标 `规则兜底`

---

## 3. 每个 agent 看到什么（用户明确要求：不要复杂人设）

固定 4 块，约 600–900 tokens：

```
【你】代号 Delta；能力 写码62/研究48/设计35；钱包 0；声誉 78；上轮到手 -3
【本轮单子】修复网站登录问题；奖励 100；难度 40；要写码
【其他人】Grove(写码58) 说"79 金币我能做"；Boreal(研究55) 说"这单太薄我不接"
          Flux(设计51) 上轮背叛过你一次
【你的处境】单独拿下要 42 成本、预计利润 3；拉 Delta+Astra 成功率 60%，可谈 70/30
```

- **自己的禀赋放最前、信息最全**（角色代入感来自"我的账本"，不是人设小作文）
- 别人只给"能力 + 上一轮公开说的一句话 + 是否背叛过你"——足够博弈，不超 token
- 风格只用 3 个标签约束：`稳健 / 激进 / 精算`

---

## 4. 输出 schema（严格，可校验）

```json
{
  "thinking": "他压到 66 了，我 79 拿不到，拉 Astra 组队还能剩 12",
  "intent": "team",
  "target": ["Astra"],
  "terms": { "share": 0.7, "deposit": 20 },
  "bid": { "taskId": "t-102", "fraction": 0.78 },
  "confidence": 0.61
}
```

校验规则（不满足就兜底，不静默改）：

| 字段 | 约束 |
|------|------|
| `share` | 0–1 |
| `deposit` | ≤ 钱包余额 |
| `fraction` | 报价 ≥ 成本线（赢家诅咒） |
| `target` | 必须在场且非自己 |
| `thinking` | 截断到 40 字上屏，全文进日志 |

---

## 5. 观众侧怎么呈现（这才是卖点）

- **心流气泡**：只显示 `thinking` 前 40 字，0.4 秒一条依次出现，7 条后自动滚
- **信任条 + 背叛高亮**：谁被背叛，红色闪一下，信任 −N 的差值当场飘字
- **角标纪律**：`LLM 实时` / `规则兜底` 必须可见，禁止把兜底伪装成"AI 在思考"
- 可重播、可导出图片/JSON（沿用现有 `事件历史` 能力）

---

## 6. 技术栈

```
浏览器  ──(SSE /games/:id/round)──  Fastify (packages/server)  ──►  LLM Provider
                                     ↑ key 只在这里                (OpenAI 兼容)
                                     └ simulation 引擎结算
```

- **key 绝不下发前端**；前端只收 `thinking` / `terms` / `settled` 事件
- Provider 抽象保留两种实现：
  - `PerAgentLlmProvider`（新，8 路并行，主路径）
  - `LlmAgentDecisionProvider`（现有批量版，降级/省钱路径）
- 模型可换：DeepSeek / GLM / GPT 同一套 OpenAI 兼容协议；`AI_CIV_AGENT_MODE=llm`
- 缓存：system prompt + 静态禀赋走前缀缓存，省 30–50% 输入 token
- 并发：8 路并发上限 8，QPS 限流 3，防 429

---

## 7. 成本与延迟估算

| 项 | 估算 |
|----|------|
| 单路输入 | ~800 tokens |
| 单轮合计 | ~6.4k in + ~1k out |
| 单轮成本 | 小模型约 $0.001（30 轮约 3 美分） |
| 首句上屏 | 0.3–0.6 秒（流式） |
| 整轮收齐 | ~2 秒（8 路并行） |

对比现状：批量单请求首字更慢（要等 8 个 agent 全部生成完），且 8 个 agent 共用一个上下文，
视角是"文明的集体策略"，不是"每个 agent 各自算计"——这正是要改掉的。

---

## 8. 落地顺序

| 阶段 | 内容 | 可验收标准 |
|------|------|-----------|
| **P0**（先做） | `PerAgentLlmProvider` + 8 路并行 + schema 校验 + 兜底 + 心流气泡（先整轮返回，不做 SSE） | 同一 fixture 下 8 条 thinking 互不相同且提到他人 |
| **P1** | SSE 逐条流式、下一轮预热、成本/延迟面板 | 首句 < 0.8s 上屏；超时自动兜底不崩 |
| **P2** | 多模型混战（不同 agent 用不同模型） | 混战后博弈行为有可测差异 |

P2 才是真正的看点：**不同模型坐一张桌子**，谁更会结盟、谁先背叛，可以直接对比。

---

## 9. 验收清单

1. 8 个 agent 的 thinking 不重复、且至少 3 条引用了他人的报价/承诺
2. 断网 / 超时 → 出现 `规则兜底` 角标，界面不崩，结算照常
3. 30 轮内 thinking 的 3-gram 重复率 < 20%（防模板化）
4. 同一 seed + 同温度下可复现（记录 seed 与模型版本）

---

## 10. 现在缺的唯一硬条件

API key。代码已留口子（`LlmAgentDecisionProvider`），缺的是：

```env
LLM_BASE_URL=https://api.deepseek.com   # 或任何 OpenAI 兼容端点
LLM_API_KEY=sk-...
LLM_MODEL=deepseek-chat
AI_CIV_AGENT_MODE=llm
```

拿到 key 后 P0 大约是一次会话可完成的工作量（provider + 校验 + 气泡）。
